When a method is invoked on a record variable with dot-notation, the method already operates on that record through the implicit `Rec` variable. Passing the same variable back as an argument does nothing — both the caller and the callee are looking at the same record instance. The extra parameter obscures the real parameter list and can mislead a future reader into thinking the method needs an *external* record when it does not.

The same applies inside a table, page, or extension that calls a sibling method and passes `Rec` explicitly: the callee already has access to `Rec`, so the argument is redundant.

Remove the redundant parameter from the call site and the corresponding parameter definition from the method signature.

### Example: external call

The following code passes `Customer` to a method that is already invoked on `Customer`:

{{< highlight al "hl_lines=7" >}}
codeunit 50100 MyCodeunit
{
    procedure MyProcedure()
    var
        Customer: Record Customer;
    begin
        Customer.DoSomething(Customer); // Unnecessary record parameter in method call [LC0096]
    end;
}
{{< /highlight >}}

Remove the redundant parameter and update the method signature:

{{< highlight al "hl_lines=7" >}}
codeunit 50100 MyCodeunit
{
    procedure MyProcedure()
    var
        Customer: Record Customer;
    begin
        Customer.DoSomething();
    end;
}
{{< /highlight >}}

### Example: internal call

Inside a table, passing `Rec` to a sibling method is equally redundant:

{{< highlight al "hl_lines=10" >}}
table 50100 MyTable
{
    fields
    {
        field(1; Name; Text[100]) { }
    }

    procedure Validate()
    begin
        DoSomething(Rec); // Unnecessary record parameter in method call [LC0096]
    end;

    procedure DoSomething(var MyTable: Record MyTable)
    begin
    end;
}
{{< /highlight >}}

To fix this, remove the parameter:

{{< highlight al "hl_lines=10 13" >}}
table 50100 MyTable
{
    fields
    {
        field(1; Name; Text[100]) { }
    }

    procedure Validate()
    begin
        DoSomething();
    end;

    procedure DoSomething()
    begin
    end;
}
{{< /highlight >}}

### Exception

The rule suppresses the diagnostic in several cases where the parameter is intentional:

- **Event publishers**: passing `Rec` to an event is idiomatic AL — subscribers need the record context.
- **Public or internal page methods**: on a page or page extension, only `local` methods are flagged. Public and internal methods that accept the source record are considered intentional API design for decoupling and testability.
- **Different module**: when the target method is defined in a different module, the developer cannot refactor the external signature.
- **Built-in methods**: calls to built-in methods (`Clear`, `Page.RunModal`, etc.) are excluded.
- **Different variable or field access**: `Customer.DoSomething(Customer2)` or `Customer.DoSomething(Customer."No.")` are not flagged because the argument is not the same record instance.
- **`xRec` arguments**: `Rec.AssistEdit(xRec)` or `DoSomething(xRec)` passes the previous version of the record, a deliberate pattern whose need the callee decides; only `xRec.DoSomething(xRec)` is flagged.
- **`RecordRef` arguments**: a `RecordRef` is its own buffer, not `Rec`, even after `RecRef.GetTable(Rec)`, so passing it is never redundant.

### Edge case: local method called with multiple record instances

A local procedure that takes a record parameter may be called with several different record instances — some of them `Rec`. The diagnostic still fires on the `Rec` call, but the other callers still need the parameter.

{{< highlight al "hl_lines=13" >}}
table 50100 MyTable
{
    fields
    {
        field(1; Name; Text[100]) { }
    }

    procedure Validate()
    var
        Other: Record MyTable;
    begin
        DoSomething(Other);
        DoSomething(Rec); // Unnecessary record parameter in method call [LC0096]
    end;

    local procedure DoSomething(var MyTable: Record MyTable)
    begin
    end;
}
{{< /highlight >}}

Invert the delegation: move the implementation into a parameterless procedure that works on `Rec`, and let the procedure with the parameter call it on that parameter. `MyTable.DoSomething()` passes no argument, so the diagnostic no longer fires, and a `var` parameter keeps referring to the caller's record. A `local` procedure cannot be called on another record instance, so both procedures become `internal`, which still keeps them inside your app.

{{< highlight al "hl_lines=13 16-19 21-24" >}}
table 50100 MyTable
{
    fields
    {
        field(1; Name; Text[100]) { }
    }

    procedure Validate()
    var
        Other: Record MyTable;
    begin
        DoSomething(Other);
        DoSomething();
    end;

    internal procedure DoSomething()
    begin
        // implementation, using Rec
    end;

    internal procedure DoSomething(var MyTable: Record MyTable)
    begin
        MyTable.DoSomething();
    end;
}
{{< /highlight >}}

Once no caller needs the procedure with the parameter any more, delete it.

If the procedure must stay `local` and takes the record by value, a parameterless overload can instead assign `Rec` to a local variable and pass that (`MyTable := Rec; DoSomething(MyTable);`). Do not use this copy for a `var` parameter: the callee would change the local copy, not `Rec`.

### Public procedures and dependent apps

Removing the record parameter from a public procedure changes its signature, which breaks every app that depends on yours; AppSourceCop reports it as [AS0024](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/analyzers/appsourcecop-as0024). Use the same inverted delegation and mark the procedure with the parameter as obsolete, so dependent apps can move to the new overload over a release cycle before you remove it:

{{< highlight al "hl_lines=8-12" >}}
table 50100 MyTable
{
    procedure DoSomething()
    begin
        // implementation, using Rec
    end;

    [Obsolete('Replaced by the overload without the record parameter.')]
    procedure DoSomething(var MyTable: Record MyTable)
    begin
        MyTable.DoSomething();
    end;
}
{{< /highlight >}}

For a `local` procedure there are no outside callers: remove the parameter directly, or delete the procedure with the parameter once your own callers no longer need it.
