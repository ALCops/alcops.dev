AL developers commonly assign string literals like `'Unfavorable'` to a `StyleExpr` variable to control page field styling at runtime, or store them in locked label constants for reuse. A misspelling — `'Unfavourable'` — compiles without error but silently produces no styling, because the runtime does not recognize the value.

Since Business Central 2024 Wave 2 (BC25), the [`PageStyle`](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/methods-auto/pagestyle/pagestyle-option) datatype provides IntelliSense and compile-time checking. Use `Format(PageStyle::Value)` instead of string literals.

### Example

The `StyleExpr` property on page fields accepts a text variable that controls the field's style at runtime. This pattern commonly uses string literals:

{{< highlight al "hl_lines=19" >}}
page 50100 MyPage
{
    layout
    {
        area(Content)
        {
            field(Amount; Rec.Amount)
            {
                StyleExpr = AmountStyle;
            }
        }
    }

    var
        AmountStyle: Text;

    trigger OnAfterGetRecord()
    begin
        AmountStyle := 'Unfavorable'; // Page style should not use string literal [LC0086]
    end;
}
{{< /highlight >}}

Use `Format(PageStyle::Value)` to get compile-time validation:

{{< highlight al "hl_lines=19" >}}
page 50100 MyPage
{
    layout
    {
        area(Content)
        {
            field(Amount; Rec.Amount)
            {
                StyleExpr = AmountStyle;
            }
        }
    }

    var
        AmountStyle: Text;

    trigger OnAfterGetRecord()
    begin
        AmountStyle := Format(PageStyle::Unfavorable);
    end;
}
{{< /highlight >}}

Locked labels are also used to store style values for reuse. This pattern triggers the rule as well:

{{< highlight al "hl_lines=4" >}}
codeunit 50100 MyCodeunit
{
    var
        UnfavorableTok: Label 'Unfavorable', Locked = true; // Page style should not use string literal [LC0086]
}
{{< /highlight >}}

Replace the locked label with a procedure that returns the formatted value:

{{< highlight al "hl_lines=3-6" >}}
codeunit 50100 MyCodeunit
{
    procedure GetUnfavorableStyle(): Text
    begin
        exit(Format(PageStyle::Unfavorable));
    end;
}
{{< /highlight >}}

### When the diagnostic is reported

The rule uses **case-sensitive** matching. Only PascalCase values matching the exact `PageStyle` enum names are flagged:

| Literal | Flagged | Reason |
|---|---|---|
| `'Standard'` | Yes | Exact match to `PageStyle::Standard` |
| `'STANDARD'` | No | All-caps convention indicates a data constant |
| `'standard'` | No | Lowercase indicates a data constant |

Valid `PageStyle` values: `None`, `Standard`, `StandardAccent`, `Strong`, `StrongAccent`, `Attention`, `AttentionAccent`, `Favorable`, `Unfavorable`, `Ambiguous`, `Subordinate`.

### Exception

The rule applies one fixed set of contexts to every `PageStyle` value, so you can tell from the code alone whether a literal is reported. It does not report a string literal that represents data or user-facing text rather than a style value:

- **Method and attribute arguments**: any call, built-in or your own, such as `SetRange(Code, 'None')`, `StrSubstNo('%1', 'Standard')` or `Assert.AreEqual('Strong', ...)`, and attribute arguments such as an event name in `[EventSubscriber(...)]`
- **Comparisons**: operands of `=`, `<>`, `<`, `<=`, `>`, `>=` and elements of an `in [...]` list, also in parentheses, as part of a range, or as a branch of a `? :` expression
- **Case labels**: `'None':` or `'Attention'..'Unfavorable':` (a literal in the statement after the label is still reported)
- **Property values**: `Caption = 'Standard'`, `Description = 'Standard'`, and also `StyleExpr = 'Standard'`, which already uses the string in the correct property
- **Unlocked labels and report labels**: `Label 'Unfavorable'` or `StandardType = 'Standard';` in a report's `labels` section without `Locked = true` is translatable text
- **Multilanguage text**: `TextConst ENU = 'Standard'` and the legacy `label(StandardType; ENU = 'Standard')` report label, which have no `Locked` option
- **Enum and enum value definitions**: string literals in enum contexts are identifiers
- **Table field assignments**: `Customer.Name := 'Standard'` writes data

Assignments to other variables (including array elements and both branches of a `? :` expression), `exit('...')`, and locked labels or report labels are reported. A style value passed to a helper method as an argument, such as `SetStyle('Unfavorable')`, is not reported.

In rare cases, a PascalCase string literal genuinely represents data — for example, a locked label `'Standard'` used as a configuration value. Use a pragma directive to suppress the diagnostic:

{{< highlight al "hl_lines=4-6" >}}
codeunit 50100 MyCodeunit
{
    var
#pragma warning disable LC0086
        ConfigValueTok: Label 'Standard', Locked = true; // configuration value, not a page style
#pragma warning restore LC0086
}
{{< /highlight >}}
